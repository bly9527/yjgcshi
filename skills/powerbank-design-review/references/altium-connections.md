# Altium 连接复原中的关键经验

本说明用于已有 SchDoc/PcbDoc 的只读分析。优先使用可用的原生导出/编译网表；自写二进制读取器时声明版本与覆盖范围。不要把以下观察假设为所有 Altium 版本的固定格式。

## 元件身份：优先核实当前位号

Components6 中的 `SOURCEDESIGNATOR` 可能是旧来源位号。同一板的两个不同 MOS 可能都留着旧 Q3，按它分组就会出现“同一脚连接两个电源”的假错误。

可用 Texts6 中附属于元件且标记为 isDesignator 的文字识别当前位号，同时保留组件索引、UniqueID、来源位号和候选文字。候选不唯一、缺失或仅为特殊字符串时标为未决；不要无条件抛弃来源值。文本记录不证明该文字在当前 GUI 中可见或已求值。

Unicode 文本可能在 WideStrings6。已验证的一类格式中，空字符串长度 ≤2 时没有后续字符串载荷；错误推进两个字节会破坏后续条目。对该格式遍历应恰好抵达流末尾；异常长度直接停止该流并报告，不能吞掉错误继续产出似是而非的位号。

## 引脚与焊盘不可用数量等同

- SchDoc 引脚按 OwnerIndex、当前 Part 和 DisplayMode 归属；隐藏部分或其他显示模式不能重复计入。
- PCB 的 0、9、空编号可能是散热/辅助焊盘；同一电气脚也可能有多个物理焊盘。保留重复编号及坐标，不要按字典静默覆盖。
- 网络未分配只表示保存记录为空，不能据此宣布悬空、不贴装或物理开路。
- Pin Name、封装 PATTERN 也会有库内残留。MOS 的 G/S/D 含义要结合准确器件 pin map 和驱动网络，不只看符号中的一个名字。

## 几何网表不是标签列表

导线端点、引脚外端、T 接点与显式 junction 可形成连接；两条导线内部交叉、无结点时不能直接短接。同名标签的合并要服从文档层级与标签类型，不能跨所有页面或所有项目全局合并。

若原图为单页且标签作用域确定，可建立严格几何图，并另列近接候选。不要为“让网表对上 PCB”使用任意容差补线；微小间隙可能涉及原生编译容差、内部等效脚或符号画法。未验证原生规则前，称为候选，不称为开路故障。

每个连通分量保存原始记录与偏移、引脚、标签、结点和合并理由，便于追查跨线误合并。跨 Sch/PCB 对照宜同时比较：当前位号+脚号、两端网络集合、网络成员/别名与元件方向。

## 将差异分型后再处理

| 现象 | 核对方式 |
| --- | --- |
| 明确无方向的电阻/陶瓷电容 1/2 对调 | 比较两端网络集合；保留 ECO 映射问题，避免当成电气连错 |
| 极性电容 1/2 对调 | 核对符号正负定义、封装脚号、丝印与实物，不能套用无极性规则 |
| 板间连接器端脚互换 | 检查正反面、镜像封装、配接视角与线束，不因两块板同号就认定直通 |
| BAT- 与 P-/GND 不同 | 跟踪中间保护 MOS/分流电阻，不能当作地别名 |
| 原理图没有 PCB 某元件 | 查子板拆分、额外连接器、改版和装配选项，不直接判漏件 |
| 同一来源位号对应多元件 | 先校正当前位号身份，再判断网络冲突 |

## 解析校验与几何限制

检查记录类型、长度、流边界、Header 记录数、元件/网络索引范围和未知结构；保存错误及未解析图元。坐标单位、Y 轴方向与层编号必须显式声明。抽取关键位号时用原始字节或第二种独立方法复核，不仅再次调用同一函数。

Pads6 的网络分配不等于实际铜连接。仅解析 Tracks6/Vias6 不能覆盖 Region、Fill、Arc、polygon、内电层等；漏掉这些对象时，“图上没有线”不能证明开路。只画焊盘中心与线段的图标为定位图，不能当制造预览。

字段格式可以参考 KiCad 官方代码中的 `APAD6`、`AVIA6`、`ATRACK6`、`ATEXT6` 和 `ReadWideStringTable`，使用时记录所查提交/文件哈希并确认与输入版本相容：

- [KiCad Altium PCB 解析实现](https://github.com/KiCad/kicad-source-mirror/blob/master/pcbnew/pcb_io/altium/altium_parser_pcb.cpp)
- [KiCad Altium 二进制读取实现](https://github.com/KiCad/kicad-source-mirror/blob/master/common/io/altium/altium_binary_parser.h)

参考第三方代码时遵循其许可。该 Skill 不包含这些源码，也没有将参考读取器或文件解析校验当作已运行 KiCad/嘉立创导入。
