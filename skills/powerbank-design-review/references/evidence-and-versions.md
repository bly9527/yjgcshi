# 证据、版本与装配状态

## 文件配套比文件名更重要

同名文件可能只有芯片后缀变化，也可能同时改变 UniqueID、子板引脚或采购要求。分别保存路径与内容哈希；重复副本属于一个内容，不能以路径数量充当研究覆盖量。相同内容的重命名也不能当改版。

BOM 的文件名、表头版次、变更履历、正文要求可能不同步。把这些字段并列记录，不自行合成“最终发布版”。发现 A3 文件含 A4 履历时，结论应为“存在 A4 变更记录，发布配套待核”，而非自动将所有 A3 图纸升级。

设计配套建议记录原理图 SHA、各子板 PCB SHA、BOM 内部版次、需求版次、固件校验/版本和发布变更依据。只有部分字段吻合时，用“配套线索”，不要写“完全配套”。

## 读取 BOM 的易错点

- 表头方案简称不能覆盖明细采购后缀。封装名、Comment、采购料号分别存储，避免某个旧库名被误当芯片型号。
- 位号行同时有主料和替代料，不代表装多颗器件。相同位号跨多行出现时，先看替代关系与适用版本。
- NC/DNP 行可能仍有数量 1；不能仅求和得出贴装数量。标注空缺则记录装配状态未知，不补成装或不装。
- 原理图画有两个同网 NTC，不证明实际并联；要先核对两个位置的装配选项。
- 对 `.xlsx` 同时保留公式与缓存。缓存缺失不等于零；不得为读取而自动重算并覆盖源文件。读取旧 `.xls` 时记录转换或解析方式，避免转换结果被当原始证据。
- 跨版本逐格 diff 适合发现变化，但插行会造成大量伪差异。再按位号、物料码、功能名和板面分组对齐，说明对齐是否唯一。

## 不同层面的数值不能互相覆盖

正常充电目标、电芯允许上限、保护 IC 检测/恢复阈值、测试电源设置和实测动作值分别记录。待机电流也需区分整机/PCBA、正常休眠/运输模式、测试供电与进入条件。

电池串并数从需求字段和实际接线双向核对，不由商品容量名推断。区分单节 Ah、电池组 Ah、Wh 与 USB 输出可用容量。

不可能温区、互相冲突的限值或跨型号复制的需求不能静默修正。比如 `低温上界 > T ≥ 高温下界` 没有解时，应保存原文，指出矛盾并找版本/勘误，不能自行改为逻辑“或”。

## 芯片手册的适用范围

记录完整订货后缀、手册版本、PDF 页序/印刷页码、寄存器地址/位域及测试条件。系列指南与具体芯片指南存在不同参数时，先分清适用节点与版本，不能只按文件日期决定覆盖关系。

图示、正文、参数表、寄存器默认值冲突时保留双方。涉及充电电压、保护温度、配置脚上下拉和 reserved 位的歧义，不产生可直接写入芯片的配置。硬件电阻设定与固件覆盖位应一起记录。

NTC 换算需要实际阻值、B 值/阻温表、上拉/激励档、ADC 比例和返回参考。不能将不同通道的温度计算公式通用化。

PDF 文本解析可能把列错位、丢掉负号/µ/Ω，必须回看原表。寄存器电压比较阈值与电流门限不是同一种量；典型值也不能代替极限公差或全温参数。

## 最小证据记录

```json
{
  "claim": "某采样电阻一端连接电池负端",
  "scope": {"model": "示例型号", "revision": "选定版本"},
  "source": {"path": "仅在本地证据库保存", "sha256": "完整哈希"},
  "locator": {"page": 1, "designator": "RS1", "pin": "1"},
  "observed": {"net": "BAT_MINUS"},
  "evidence_kind": "pcb_saved_pad_net",
  "status": "observed",
  "limitations": ["尚未求解全部铜连接", "不是硬件实测"]
}
```

`evidence_kind` 可区分文件索引、图纸文字、原理图几何、PCB 保存网络、BOM 装配、手册参数、EDA 检查和实测。推断使用 `status=inferred` 并引用依据；差异保存双方，状态为 unresolved。不存在一种跨场景永远优先的来源：选料看已批准 BOM，连线看配套工程，阈值看确切后缀及条件，实际行为看有效测量。
